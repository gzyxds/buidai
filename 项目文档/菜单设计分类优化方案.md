# 菜单设计分类优化方案

> 日期：2026-10-02
> 状态：已实施
> 范围：仅导航菜单（桌面端 + 移动端）的信息架构与分类重排，不动页面内容
> 决策记录：采用方案 A（产品中心 Mega Menu）；「优刻云计算」保留一级不动

## 一、现状梳理

当前一级菜单共 **8 项**（[components/AppNavigation.vue](../../components/AppNavigation.vue)）：

| # | 菜单项 | 目标 | 类型 |
|---|--------|------|------|
| 1 | 首页 | `/` | 页面 |
| 2 | 私有部署 | `/buidai` | 商业页 |
| 3 | 智言AI | `/agent` | 品牌页（核心产品） |
| 4 | 解决方案 ▾ | 下拉 15 项 | **混合** |
| 5 | 定价方案 | `/pricing` | 页面 |
| 6 | 资源中心 ▾ | 下拉 4 项 | 内容聚合 |
| 7 | 产品演示 | `/demo` | 页面 |
| 8 | 优刻云计算 | 外链 `cloudcvm.com` | 合作伙伴 |

「解决方案」下拉的 15 项实际构成：

- 2 个导航入口：应用中心 `/plugin`、解决方案 `/solutions`
- 12 个产品详情：香蕉绘画 / 网文短剧 / 数字人系统 / 即梦AI视频 / 即梦AI绘画 / 电商试衣 / AI音乐 / AI PPT / AI简历 / Sora视频 / 视频混剪 / 小红书助手（对应 `data/products/detail/*.ts`，均挂在 `/product/*` 下）
- 1 个索引入口：查看全部产品 `/product`

## 二、问题诊断

1. **概念混淆**：「解决方案」下拉里 80% 是产品而不是方案。用户想找产品时，第一直觉不会点「解决方案」，找不到还会以为产品没上菜单。
2. **15 项平铺无分组**：12 个产品混排在一起，扫描成本高。产品本身有自然的能力分类（绘画 / 视频 / 写作 / 办公），却没有用起来。
3. **一级菜单超载**：8 项已到认知上限，「优刻云计算」外链与站内导航同级，干扰主任务路径；「产品演示」「应用中心」「产品中心」三个概念互相重叠。
4. **概念重叠**：`/plugin`（应用中心）、`/product`（产品中心）、`/demo`（产品演示）都是产品类入口，分散在三个位置。

## 三、优化方案

### 方案 A（推荐）：以「产品中心」为核心的分组 Mega Menu

一级菜单精简为 **6 项**：

```
首页    智言AI    产品中心 ▾    解决方案    定价方案    资源中心 ▾
```

- **产品中心 ▾**（桌面端分组 Mega Menu，替代原「解决方案」下拉）：

| 分组 | 产品 |
|------|------|
| AI 绘画创作 | 香蕉绘画、即梦AI绘画、电商试衣 |
| AI 视频创作 | 即梦AI视频、Sora视频、视频混剪、数字人系统 |
| AI 智能写作 | 网文短剧、小红书助手、AI简历 |
| AI 效率办公 | AI PPT、AI音乐 |

  面板底部操作行：**查看全部产品** `/product` ・ **应用中心** `/plugin`

- **资源中心 ▾**：更新日志、技术博客、文档中心、资源下载、**产品演示**（并入）
- **私有部署** `/buidai`：保留为一级（B2B 转化入口），位置移到「定价方案」之后
- **优刻云计算**：移出主菜单 → 放入资源中心下拉，或移入页脚生态区（见待确认项 2）

预期效果：菜单结构 = 品牌（首页/智言AI）→ 产品（产品中心）→ 商业（解决方案/定价/私有部署）→ 内容（资源中心），信息架构清晰；产品按能力分组后一次可扫完。

### 方案 B：保守瘦身（7 项）

保留方案 A 的「产品中心」分组面板，但一级菜单维持：

```
首页  智言AI  产品中心 ▾  解决方案  私有部署  定价方案  资源中心 ▾
```

即：只把「解决方案」下拉改名拆分为「产品中心」，其余一级项（含优刻云计算）位置不动。

### 方案 C：最小改动（8 项）

一级结构与文案全部不变，仅在下拉内给 12 个产品加 4 个分组小标题（分组方式同方案 A）。改动量最小，但「概念混淆」问题不解决。

## 四、移动端联动

移动端菜单（宫格 + 子菜单视图）同步按新结构重排：

- 一级宫格：首页、智言AI、产品中心（展开子菜单）、解决方案、定价方案、资源中心（展开子菜单）、私有部署
- 「产品中心」子菜单内按 4 个分组显示**分组小标题 + 产品列表**（现有子菜单视图加分组标题即可，无需新组件）
- 优刻云计算按待确认项 2 处理

## 五、实施范围

| 文件 | 改动 |
|------|------|
| `components/AppNavigation.vue` | 重写 `items` 配置；桌面端用 `item-content` 插槽实现分组 Mega Menu（UNavigationMenu 支持嵌套 children + 插槽，无需新依赖）；移动端子菜单加分组标题 |
| 其他页面/组件 | 不动 |

## 六、决策记录（2026-10-02 确认）

1. **方案选择**：✅ 方案 A（产品中心 Mega Menu）
2. **优刻云计算去向**：✅ 保留一级不动（位于资源中心之后，维持原相对位置）
3. **私有部署**：✅ 保留为一级，移至「定价方案」之后

## 七、实施说明

- 桌面端：`UNavigationMenu` 使用 `slot: 'products'` + `#products-content` 插槽实现分组 Mega Menu（4 组能力分类 + 底部「查看全部产品/应用中心」入口行），面板宽度 760px；`viewport`/`content` 配置按官方文档改为动态宽度（`--reka-navigation-menu-viewport-width`）
- 移动端：`flattenNavigationItems` 支持两级嵌套（分组 → 产品），`currentSubmenuGroups` 按 `groupLabel` 归并，子菜单视图渲染分组小标题
- 数据源：`productMenuGroups` / `productMenuFooter` 为桌面与移动端共用的单一数据源
- 验证：`npm run typecheck`、`eslint`、`vitest`（23 用例）全部通过；浏览器实测桌面 Mega Menu 与移动端子菜单均正常
